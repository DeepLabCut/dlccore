# Labeled-data fixtures

Samples of what two specific writers produce. They are not a reference for valid labeled data, and they do not represent the historical DeepLabCut data in use. Not covered, among others: files written by DeepLabCut's labeling, `merge_annotateddatasets`, `convertcsv2h5` or outlier extraction; files written by DeepLabCut 2.x; multi-animal conversions that append keys; several scorers in one file; napari's frame-extraction writer.

The fixtures are committed bytes, so nothing at test time needs a producer installed. Each producer is an exact tree or release, and regenerating anywhere else changes the bytes.

## Written by napari-deeplabcut

Generated by a script run against a local napari-deeplabcut checkout.

- **Producer**: napari-deeplabcut commit `d50015d0dd4762ed2ff20e2fb51de590df297cdb` (version `0.3.1.2.dev5+g17d14f36e`), captured 2026-09-02.
- **Write primitive used**: `napari_deeplabcut.core.io._atomic_to_hdf` with the real `DLC_CANONICAL_H5_KEY` ("df_with_missing") — the same function `write_hdf` calls internally. This does **not** exercise the full NPE2 `write_hdf` contract (Points-layer/provenance validation), nor napari's other writer, frame extraction in `ui/cropping.py`.
- **Shapes**: verified against napari-deeplabcut's own conventions (its `conftest.py` fixture builders, and `restore_dlc_on_disk_header_shape`'s single-animal column collapse), not invented.

## Written by DeepLabCut

- **Producer**: `deeplabcut` 3.0.2, the registry release installed by `uv` (no local source), on Linux; Python 3.12.14, pandas 2.3.3, PyTables 3.11.1, numpy 2.5.3. `multi_animal_unique_bodyparts.h5` captured 2026-10-10, every other file 2026-10-12.
- **Write paths**, each on a project config written by `auxiliaryfunctions.write_config`, each call writing an `.h5` and its `.csv` twin:
  - `deeplabcut.utils.auxfun_multianimal.convert_single2multiplelegacyAM(config, userfeedback=False, target="multi")`, from a hand-built 3-level single-animal file whose multi-animal bodyparts are named `<individual>_<bodypart>`. Nothing in DeepLabCut calls this function; the header shape it writes is the one labeling writes;
  - `deeplabcut.generate_training_dataset.trainingsetmanipulation.dropduplicatesinannotatinfiles(config)`, from a hand-built single-animal file with a flat string row index and one row twice.
- **Only these paths**: DeepLabCut's labeling and `convert2_maDLC` write the same header shapes by other code; neither is exercised here.
- **Bytes are not reproducible**: HDF5 stamps every object with its write time, so a rerun writes a different `.h5` holding an equal table. The 2026-10-10 and 2026-10-12 runs differ in 72 bytes across 24 objects, all timestamps. Each `.csv` reads back equal to its `.h5` twin (`tests/io/labeled_data/wide/test_csv.py`).

## Why `keypoints` appears here

`keypoints` is not a hypothetical legacy key. It is **napari-deeplabcut's own write key**, used from its first functional release (2022-05-12) until it switched to `df_with_missing` (2026-04-27). DeepLabCut has written `df_with_missing` since its first commit (2018-04-10).

**Both projects read keyless**; `pd.read_hdf(path)` with no key succeeds for any single-key file. So a project labeled with both tools in that period legitimately holds both keys, one per video folder.

A `keypoints` file is therefore real labeled data produced by the GUI DeepLabCut ships for labelling, not a corrupt or exotic file. Fixtures covering it exist so that stays true. The registry entry asserting it is `LEGACY` is pinned by `tests/io/labeled_data/wide/test_h5.py`.
